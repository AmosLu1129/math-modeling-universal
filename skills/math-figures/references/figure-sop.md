## 0. 铁律（违反即返工，无例外）

1. **先写一句话结论，再决定画什么。** 说不出一句话结论的图不该存在。
2. **画的每个数字必须可溯源**——落到 `results.json` 的 `meta.params`，禁止图上出现正文查不到出处的数。
3. **不编造数据点**：不插值伪造、不四舍五入回灌、不把示意数据画成实测数据。
4. **不画没采样的范围**：柱/线/带的跨度必须对应真实采样区间，禁止外推出的"看起来很完整"。
5. **实测与模型必须可区分**：拟合曲线与观测点、预测与真值，形态或标记必须能分辨。
6. **不确定性与 n 必须交代**：误差棒类型（SD/SEM/95%CI）与 n 写进图注，不在图内堆字。
7. **参考图只教结构，绝不搬运结论**：参考文献的数字、结论、患者信息一律不得出现在本图。

## 1. 理解已有图，再规划新图

规划前先按页面尺度 + 放大尺度**实际打开**每一张已有图（不是看文件名、不是看题注）。
对整图与每个面板分别记录：

- 科学问题是什么，**唯一的主结论**是哪一个；
- **hero 面板**（主结论在此变得可见的那一块）是哪个；
- 每个面板的职责：铺垫 / 机理 / 主结果 / 对比 / 消融 / 诊断 / 边界 / 解释；
- 哪些是**实测**、哪些是**推断**、哪些只是**示意**；
- 可见的方法、数据、指标、基线、单位、不确定性、样本量、统计标记；
- 预期阅读顺序，以及一个认真读者能自己读出的结论；
- **像素与源数据/题注/正文之间的矛盾**——发现矛盾必须回到源头解决，不能改题注糊过去。

> 数据缺陷实测教训：曾出现"图的每根柱子都与声明不符"的情况（关键词误匹配混入误导性
> 负相关柱 −0.164）。**聚合结论图/表画之前，先跑一次逐条核对脚本**，把每条柱子的数字
> 打印出来与声明比对；负值/异常值要问自己"这根柱子代表什么、为什么是负的"。

## 2. 决定论文需要哪些视觉论证

在固定图型与图数**之前**，先按论证阶段规划全局覆盖（三类图体系见 SKILL.md）。对每个
需要的视觉任务，从 `keep` / `redesign` / `create` 中选一个：

| 决策 | 判据 |
|---|---|
| **keep** | 现有图已经承载了所需结论，且达到交付标准 |
| **redesign** | 证据有效，但层级/面板逻辑/可读性/视觉语法妨碍结论被读出 |
| **create** | 有一个有证据支撑的问题，但视觉论证尚不存在 |

**决定"不出图"必须给出与该视觉任务相关的理由**：冗余、用正文/表格表达更好、或证据缺失。
不能因为"难画"而省略。

## 3. 先定论证契约，再组织版面

这是 paper-spine 与旧流程差异最大的一步：**在写绘图代码之前**，把下表填完（写进
`work/figures/figure_plan.md` 或图注草稿，不要求 JSON）。

### 3.1 整图级

- **一句话结论**（要捍卫的命题，不是"方案对比"这种话题）："高剂量在第 12 周把评分较基线
  降低 11.0 分（95%CI −14.8~−7.2），其余组无差异"——不是"各组评分变化对比"。
- **图面原型**（见 3.3 四种原型）。
- **hero 面板 + 阅读顺序**。
- **claim boundary**：这张图**不能**证明什么（如"不能证明因果""不能外推到其他人群"）。
- 对应的正文单元（哪一问、哪一段结论）。

### 3.2 面板级（每个面板逐条填）

| 项 | 内容 |
|---|---|
| 面板身份 | a/b/c 及其一句话问题 |
| 面板职责 | 铺垫 / 机理 / 主结果 / 对比 / 消融 / 诊断 / 边界 |
| 证据锚点 | 数据来自哪个文件/哪次运行/`results.json` 哪个键 |
| 真实字段 | 实际列名、单位、变换（如 log10）、样本量、不确定性 |
| 预期读法 | 读者看这个面板应该得出什么 |

**删并判据**：盖住某个面板，整图论点不变 → 删掉或合并。

### 3.3 四种图面原型（先选原型，再排面板）

1. **数值比较网格**——多个可比面板并列，共享轴/图例，主流对比场景。
2. **机理示意主导的复合图**——示意图占 35–60% 面积（`height_ratios=[2,1]` 之类），定量面板
   放下方或右侧；机理题必备。
3. **影像/实景 + 定量**——真实图像/截图为主面板，定量作支撑。
4. **混合模态**——上述组合，用于一个论点需要多类证据时。

### 3.4 参考解构（**可选**，拿不到参考不算失败）

参考图教的是**结构与视觉语法**，绝不是本研究的事实。

**有可用参考时**，记录：
- 来源身份（作者/期刊/年份/精确图号）与可查看素材、使用依据；
- 该图的**面板角色、标记编码、层级、阅读顺序、有价值的标注**；
- **具体哪些结构特征要迁移**、迁移到本图哪个位置；
- **哪些内容禁止迁移**（该研究的数字、结论、人群细节）。

**没有可查看的合法参考时**：**明确记录"本图为原创设计"及该限制**，然后继续作图。
不要为了凑流程编造"参考学习"，也不要把自己上一版图说成"参考文献对比"。

> 参考是**设计学习**，不是分析授权：不得因为"参考里有这个分析"就去做 `materials_only`
> 范围外的新计算。

### 3.5 背景与配色底线

- 优先**透明可编辑画布 / 纯白出版底色**；避免装饰性色块、渐变、纹理。
- 只有**语义性标记**（数据标记、热力图单元、机理区域、有信息量的高亮）可以用彩色。
- 语义固定、族系一致、色盲冗余编码等硬规则见 SKILL.md「配色细则」。

## 4. 按组件路由工具（不要整图二选一）

不要先把整图归类为"数据图"或"生成图"，而是**逐组件决定生产方式**：

| 组件 | 生产方式 |
|---|---|
| 实测值、坐标轴、区间、分布 | **确定性绘图**（matplotlib 等），保留数据与脚本 |
| 标签、箭头、边界、图例、规则几何、叠加层 | **可编辑原生矢量/文本**（绘图引擎、SVG、文档工具） |
| 已有的显微/结构/权威科学图像 | **保留原始素材与出处**，不得合成为"新观测" |
| 规划中需要、但难以绘制的有机形态/纹理 | 仅生成**该受限的、无文字**的部件，再合成进原生构图 |

选择"生成组件"必须来自**具体的绘制需要**，而不是"这张图叫机理图"。
保留实际提示词与生成素材，并从工具缓存中复制到本任务目录，用**任务相对路径**引用。
**图字分离铁律**：AI 基底图内禁止依赖生成文字；合成后必须过 `svg_audit.py`。

**整图概念生成只是设计探索**：不得把一张完整带标注的位图当作可编辑组件交付。
用原生标签、连接线、实测标记组装成图——**"程序化组装"本身不等于质量通过**。

## 5. 从有支撑的结论出发设计数据图

在选定图型之前，先识别**主结论**与支撑性任务：真实分布与样本量、组件间关系、对照、
有意义的异质性、不确定性与稳健性（在已有证据范围内）。

- **可比性优先于形式统一**：可比面板统一轴范围与误差定义。
- **一个主面板 + 支撑面板**，共享图例、稳定颜色含义、只标关键结果。
- **不要为了增加复杂度而堆砌**：无关终点、无支撑的显著性、生存曲线、模型性能声明一律不加。
- 复用旧绘图脚本前**先读脚本**：它可能顺带清洗数据、拟合模型或重算统计量；在
  `materials_only` 下必须把"纯绘图"与"分析步骤"分开。
- 复杂度由**它揭示的信息**正当化，不由参考图的档次正当化。

---

## 6. 完整解释性构图先于部件生产

先定义整图的一句话信息与各区域职责，**保留有用的科学复杂度**：暴露实际的模块内部结构、
数据结构、对比层次、方法与结果之间的连接。

- 主面板更大时就让它是大的；用共享图例、对齐的小倍数、嵌套尺度、走线空间来组织细节。
- **解决拥挤靠改布局或删冗余措辞，不靠丢弃有效证据，也不靠把字号缩到"技术上塞得下"**。
- 数据标记锚定当前结果，结构锚定真实方法/代码，机理实体与箭头锚定有引用的知识或**明确标注
  的假设**；**必须保留"本研究实测"与"文献解释"之间的区别**。
- 通用方框 + 装饰性图案不能替代这项设计工作。

## 7. 与审查环节的接口

本 SOP 的产物是**可审查的契约**，交给 `visual-check.md` 的闭环：

| 本 SOP 产出 | 审查环节如何用它 |
|---|---|
| 一句话结论 | 读图复核时判断"图是否讲对了这个结论"（程序查不出语义） |
| 面板职责与证据锚点 | `layout_qa` / `svg_audit` 判定重叠时，区分"该压"与"不该压" |
| 单位、n、误差类型 | 程序核对图注是否交代；缺失即 FAIL |
| claim boundary | 防止读图复核把"不能证明的"写成"已证明" |
| 原创/参考解构声明 | 交付说明中如实标注，不得把原创说成参考引导 |

**审查发现的问题，回到本 SOP 对应条目改契约，再改代码重渲**——禁止只在预览图上修补，
也禁止只改状态/回执来"通过"。

### 7.1 灰度/色盲预览是必做项（不是可选项）

每张多系列图**必须**生成并核对灰度预览（`_grayscale.png`）与色盲模拟预览
（deuteranopia / protanopia），据此确认：

- 灰度下各系列仍可分（线型 / marker / hatch 冗余是否**真的**生效）；
- 色盲模拟下相邻系列色距是否够（估算 ΔE，而不是"看着还行"）。

> **2026-09-17 回归实测教训**：一次移植后的运行在配色决策上**考虑了**色盲（把红绿换成
> Okabe-Ito 变体），但**没有生成灰度/色盲预览文件**，于是"冗余编码是否真的生效"实际未被验证。
> **只有渲染出来的灰度/色盲图才算证据**；在报告里写一句"配色已色盲安全"不算。

### 7.2 `svg_audit.py` 字号判据的单位缺陷（**2026-09-17 已修复**）

**现象**：修复前 `svg_audit.py` 对 matplotlib 导出的 SVG **把全部文本**判成 TINY
（实测 66/66 条 FAIL），真实 7pt 的标签被折算成 5.2pt。

**根因**（已定位并已修）：字号换算写成 `fontSizePx / scale × pt_per_unit`。其中
`scale = 渲染像素宽 / viewBox 宽 ≈ 1.3333`，但 Chrome 对 SVG 文本报告的
`getComputedStyle().fontSize` **是元素在自身用户单位系里的字号，不是物理 CSS 像素**
（SVG 用户单位已由画布宽度定义，缩放后数值不变）。因此多除了一次 1.3333，字号被系统性低估 25%；
再叠加 `pt_per_unit` 由档位默认投放宽反推的偏差。

**修复**：真实字号 = `fontSizePx × unit_pt`，其中 `unit_pt` 由根元素 `width` 的单位决定——
`width="526.8pt"` → `unit_pt = 1.0`（matplotlib 属此类）；`width="600"`（无单位，CSS 像素）
→ `unit_pt = 0.75`。投放宽只在用户**显式** `--print-width-mm` 时才用于折算缩放后的有效字号
（档位默认值不代表该图真会放那么宽，拿它缩放会造出假 TINY）。

**修复后的验证**（同一张图三方对质）：

| 来源 | 最小字号 | 判定 |
|---|---|---|
| `svg_audit.py`（修复后） | 6.0pt，13 条 WARN（6.0–6.5pt 逼近下限），0 条 FAIL | 与 PDF 一致 |
| `audit_pdf_text.py`（PDF） | 6pt | PASS |
| pdfplumber 直抽 PDF 字符 | 6.0pt（分布 6.0/6.2/6.5/7.0/8.0/8.5） | 与 SVG 声明值一一对应 |

`--self-test`（3 用例 / 7 判据）修复后仍 PASS，px 画布（手写 SVG）路径也验证过。

**仍建议的交叉核对**：`TINY` 与 `audit_pdf_text.py` 的结论应一致；若不一致，以 **PDF 为准**
（PDF 是最终交付物，且不受浏览器字体度量影响）。
