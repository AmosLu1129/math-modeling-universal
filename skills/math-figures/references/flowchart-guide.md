# 技术路线图 / 流程图规范（2026-08-11 沉淀）

适用于论文「问题分析」的技术路线图（图 1）、模型结构框图、算法流程图、系统架构图。原则：**先定叙事再动笔，出图后必过自检闭环**。本规范由一次真实迭代沉淀：初版为双层线性串联（斜线箭头、双色框、高饱和），经 3 轮用户反馈收敛为下述版本。

## 一、结构设计

- **三明治分层**：数据层（输入）→ 建模层（核心方法）→ 验证与产出层（检验 + 交付）。每层左上角标编号 + 名称（① 数据层 / ② 建模层 / ③ 验证与产出层），引导阅读顺序。
- **主链与支线分明**：主证据链线性串联（如问题一→二→三）；独立模块（如并行问题四）作支线，用虚线并配独立套色，支线从数据层单独引出。
- **汇流直下不拐弯**：多条线汇入下一层时，把接收框做宽，让每条线各自**垂直直下**进入同一框；禁止"先横后竖"的 Z 形折线，也不要在汇合点之后再拐一下。
- **终点收束**：流程要有明确终点（如"论文图表与提交包"）；起点与终点可用同色，形成"始于 X、终于 X"的闭环感。
- **每层背景带**：每层用极淡的对应色系背景带（如 `#F4F6FA` / `#F5F8F4` / `#F6F5FA`），强化分层但不可喧宾夺主。

## 二、视觉规范

- **气泡单色**：填充与边框同色（不要"浅填充 + 深描边"双色）；深色块内白字。白字对比度 ≥ 4.4:1（WCAG AA），副题可用 85% 白。
- **套色**：同一主题/单元的气泡与箭头同色——箭头跟随它代表的那条流（通往哪条链就用哪条链的色）。一图 ≤ 4 个色系，每色必须有语义（数据 / 主链 / 支线 / 验证）。
- **低饱和和谐配色**：高饱和对比色（纯绿 + 纯橙）刺眼、不专业；相邻层用邻近/同族色相（蓝↔绿冷调过渡、绿↔琥珀草木系、蓝紫↔蓝呼应），四色统一为灰调、中低饱和、相近明度。推荐套色方案（2026-08-11 落地验证）：
  - 蓝（数据/产出）`#4A6A92`、绿（主证据链）`#4E7A5C`、琥珀（筛查支线）`#96713F`、紫（验证）`#5D5480`
- **灰度可分**：评审常打印黑白稿——出图后核对各色在灰度下亮度有差异（PIL 求相对亮度），防止蓝/紫同亮度在黑白下混淆；无法拉开时加深或减浅其中一色。
- **连线正交**：全部直角折线，禁止斜线；实线 = 主链、虚线 = 支线；线宽统一 2–2.5。
- **虚线与实线不重叠**：虚线与实线不得共用线段——分支虚线从框的不同端口/角引出、走不同高度，与实线完全分离；或只保留其一。
- **字号**：框题 16–18（加粗）、副题 14、图例 14；中文无衬线（PingFang SC / Hiragino Sans GB / 微软雅黑）；文字居中，每框 ≤ 2 行。
- **图例**：右下角只放色块图例（如"绿=时点主证据链，橙=异常筛查支线"）；**不写实线/虚线箭头含义条目**（箭头语义已由线型本身表达，图例只讲颜色）。

## 三、出图与验收

- **工具纪律**：优先使用跨平台方案——`matplotlib` 框图（`layout_qa.py`）或手写 SVG → `python ../_shared/scripts/render_svg.py in.svg out.png --dpi 300`。
- **SVG 根元素必须加白底 rect**（透明背景会被像素检查误判为内容触边）。
- **程序几何审计**：手写 SVG / drawio / PPT 导出必过 `svg_audit.py`（检查越界、互叠、对比度、字号与灰度可分）。
- **像素检查与原生视觉复核**（多图 ≤ 3 张/组）：对齐、文字溢出、虚线实线重叠、套色一致性、灰度可分逐项核验；改布局或配色后必须重跑。

## 四、Graphical Abstract 轻 3D 风格（2026-08-11 第二版，用户指定）

适用：追求高端学术期刊图摘要质感时，在「结构设计/视觉规范/出图验收」基础上叠加以下规则；拓扑、模块位置、文本内容必须与参考版严格一致，只改视觉呈现。

- **轻量化微 3D（禁止厚重夸张）**：每个模块 = 主体圆角矩形（圆角 rx≈10-12）+ 向下偏移 3px 的深色挤出层（同圆角）+ 柔和向下投影（feGaussianBlur stdDev 3.5、dy 3.5、黑色 20% 不透明度）+ 顶部 40% 高度白色 10% 不透明度哑光高光（用 clipPath 裁剪保证圆角）。禁止渐变、禁止炫光。
- **层级划分**：删除大面积朦胧底色背景带，改为**纤细浅灰色水平分割线**（如 `#D8DDE3` 1px）分隔三层；背景纯净浅白 `#FFFFFF`；层标签（① 数据层…）保留在左侧。
- **规范配色（语义化 + 低饱和 + 灰度可分 + 白字达标）**：
  - 海军蓝（数据/产出）`#1B3359`、森林绿（主线建模）`#2E5D3C`、赭棕（支线建模）`#81502A`、靛紫（模型检验）`#473B76`；挤出层取主色 ×0.75。
  - 实测灰度亮度 0.033/0.058/0.087/0.106（黑白可区分），白字对比度 6.7–12.7:1。
- **箭头语义统一**：实线 = 流程推进；虚线 = 迭代反馈。同一图内箭头粗细全程一致（2.5），实心小箭头；**支线/并行流属流程推进，用实线而非虚线**（虚线只留给真正的反馈回路）；路径干净不交叉——支线从源框角落引出、沿空白通道绕行（如左缘外侧），不与其他箭头共用线段或相交。
- **图例仅色块**：只放色块含义（4 项）；**不要实线/虚线含义条目**（用户 2026-08-11 明确：箭头语义由线型本身表达，图例不需要解释）。
- **样式收口**：严禁卡通画风、多余装饰、复杂纹理、强烈光影；框内文字统一白色居中；整体网格对齐、留白均衡。

## 五、同稿多工具出图对比（2026-08-11 第三版，用户要求）

同一份拓扑/配色/文案，分别用 SVG、drawio、PPT 各出一版供用户对比后，结论与工具链如下。

**效果对比**
- SVG（手写 + rsvg 渲染）：轻 3D 最受控、边缘最锐利、矢量无损，最适合进论文；缺点是改稿要改代码。
- drawio（`.drawio` 手写 XML + 官方 CLI 导出）：网格对齐最规整、自带极轻阴影、导出快、可双击继续编辑；缺点是导出有贴边裁切风险，且 3D 质感不如 SVG 可控。
- PPT（python-pptx 生成 + 原生渲染）：投影最明显、风格偏演示、团队可编辑可动画；缺点是最难做到像素级对齐与轻 3D 克制，投影易显"重"。

**结论**：论文最终稿用 SVG；需要给队友/老师可编辑稿时，drawio 或 PPT 是合理衍生版。三版必须共用同一拓扑、坐标关系、配色与文案，只允许渲染层差异，避免"同图不同版"。

**工具链与坑**
- drawio 导出：先探测系统原生安装（macOS App 在 `/Applications/draw.io.app`，**App 内 CLI 可执行名是 `draw.io`**：`/Applications/draw.io.app/Contents/MacOS/draw.io --export --format png --scale 3 --output out.png in.drawio`，本机实测可用；PATH 里没有 ≠ 没装，禁止重装）。导出的内容 bbox 可能贴到画布左/上边缘（本版实测 bbox=(2,23)），导出后必须跑像素检查确认无裁切；必要时手动在 XML 根节点加 `margin`/平移。
- PPT 渲染（重要）：**禁止用捆绑运行时的 soffice 渲染带中文的 PPT**——它被 codex-runtimes override、缺系统中文字体，渲染成方块 □；macOS 用系统原生 `qlmanage -t -s 2048 -o <outdir> <pptx>`（用系统字体渲染，中文正常）。python-pptx 里字体名写 `"PingFang SC"` 没问题（qlmanage 正常），若未来必须走 soffice 需改成 `"Heiti SC"`。
- PPT 阴影克制：python-pptx 默认预设阴影偏重，本版用 `shape.shadow.inherit = False` 后个别元素仍有投影；如需完全去阴影需逐 shape 检查，或接受"演示版投影更明显"作为工具差异。
