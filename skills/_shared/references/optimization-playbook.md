# 运筹优化题型标准求解预案

> 用途：遇到优化/规划题时，按本预案选型、预算时间、诊断收敛，避免“跑不出来才临时想招”。
> 适用范围：国赛 C 类（资源分配/排产/选址）、MCM/ICM 优化小问、多期决策等。

## 一、选型决策（先想清再写代码）

1. **连续、可微、规模小** → `scipy.optimize.minimize`（SLSQP/trust-constr），目标与约束显式可导优先。
2. **纯线性规划（LP，变量连续）** → PuLP / HiGHS；小规模直接解，大规模看稀疏结构。
3. **含整数/0-1/强结构约束（满种、最小面积、重茬、选址互斥）** → **直接 OR-Tools CP-SAT**，不要把“逻辑约束”硬转成大 M 线性化。
4. **非线性且无法解析** → 先全局粗搜（差分进化/网格/遗传）定位初值，再局部精化；记录初值与收敛过程。
5. **NP-hard 大规模、赛时不可求精确解** → 启发式 + 局部搜索 + 上界，明确报告 gap 与最优性间隙，不伪装精确最优。

## 二、LP 松弛诊断（动手前 10 分钟，先看解质量）

- 先解 **LP 松弛**：把整数变量放宽为连续，得到目标上界（最大化）或下界（最小化），判断问题规模与线性化方案是否成立。
- 松弛解若已经接近目标量级，说明问题“不紧”，可考虑直接近似或再加割平面；松弛过弱（gap 巨大）→ 线性化/建模有问题，先修模型。
- **大 M 线性化警惕**：M 取太大 → LP 松弛过弱、求解器长时间无界/无进展（2024 国赛 C 实测 HiGHS 10 分钟无可行解）；优先用 indicator 约束或 CP-SAT 原生逻辑约束。

## 三、数值缩放与整数化

- 金额/面积/比例等系数**统一放大为整数**（如 `SCALE=100`，保留两位小数）再进 CP-SAT，避免浮点误差导致的不可行或次优。
- 目标与约束同量纲归一；变量上下界给紧界（紧界 = 更快收敛 + 更好 gap）。
- 对称性问题加“破对称”约束（如给同质资源排序），显著压缩搜索空间。

## 四、CP-SAT 时间预算与提前启动

| 变量规模 | 约束规模 | 建议时间预算 | 说明 |
|---|---|---|---|
| < 1k | < 2k | 30 s – 2 min | 通常能出较优解 |
| 1k – 5k | 2k – 10k | 2 – 5 min | 先跑一轮看 gap 再定 |
| 5k – 20k | 10k – 50k | 5 – 15 min | 提前启动，边跑边落盘 |
| > 20k | > 50k | 15 – 60 min 或转启发式 | 明确报告 gap，不留“无解”空窗 |

- **提前启动纪律**：长题（> 5 min）不要串行等结果，先起后台任务、定期读日志；求解期间并行推进图表/写作等不依赖该结果的工作。
- **中途落盘**：`CpSolver` 用 `search_for_all_solutions=False` + `num_search_workers` 控线程，用 solution callback / 定时保存当前最优；不要等 `SOLVE` 返回才拿解。
- **gap 报告**：结束必须打印 `BestObjectiveBound` 与 `ObjectiveValue` 的相对 gap；gap > 10% 要声明“非精确最优”，论文如实写。

## 五、超时与不可行诊断（不要把“慢”当 bug 调参）

1. 先看是否 `INFEASIBLE`：逐条放开约束定位冲突源；给关键约束留容差（`TOLERANCE`）。
2. 再看是否 `FEASIBLE`（找到可行解但未证明最优）：这是大面积题常态，报告 gap 即可。
3. 最后看求解器参数：`max_time_in_seconds`、`num_search_workers`、`random_seed`、是否误用大 M。
4. 记录“单轮/单折计时 × 轮数”估算总耗时（2024 C 教训：LightGBM/CP-SAT 都曾因没做单次计时导致排期失控）。

## 六、结果落盘与可复现

- 每个方案的目标值、关键决策变量、gap、求解耗时、求解器版本写入 `results.json`。
- 代码头注释写清【题号/模型/功能/依赖/入口】；固定 `random_seed`，求解器参数显式给全。

## 七、循环排产 / 多目标随机预案（2026-09-03，2023 国赛 D 实测）

- **先算解析上界再上求解器**：稳态循环排产（周期 $C$、五阶段窗口 $I_s$、每栏容量 $cap_s$）的**平均占栏系数**
  $u=\frac1C\sum_s |I_s|\bar\lambda_s/cap_s$ 是闭式的，$n\le \bar P/u$ 即产能上界。
  任何 LP/CP 报出更高的 $n$ 都是实现错误信号（实测 LP 因 C7/C8 符号反了报 443.8 vs 解析 435.179）。
- **循环对称破缺**：$x_d$ 按相位循环平移等价 ⇒ 加 `x[0] >= x[d] ∀d`（不改变最优值，只砍等价解），
  配合「LP 有效不等式 + `AddFeasibleSolutionHint` + 下界提示」，229 相位 CP-SAT 从 300 s 无 incumbent 到 300 s FEASIBLE（gap 1.9%）。
- **两套口径必须并存**：设计层用 fluid + 常数取整溢价 $\delta$（规模可控），评估层用**逐日 ⌈只数/容量⌉ 精确重放**。
  两者差要量化（实测周分桶使峰值 +2 栏、出栏 −2 只/年），不能混用同一个数冒充两种口径。
- **burn-in 与管道长度**：育肥链 $M+G+L+F=419$ 天 > 周期 229 天 ⇒ 重放窗口取 `CYCLES=8` 且只用最后 3 个循环统计，
  否则"稳态指标"其实测的是管道填充期（实测需求恒为 0）。
- **无成本自由变量审计**：占用资源却不进目标的变量（存量、公羊数、库存、备用容量）必然被求解器当"免费午餐"。
  一律用守恒式或闭式定义钉住（`rest = Σ(1−其它态)`、`r=⌈n̄/50⌉`），别指望加惩罚项——那只是把漏洞换成新的调参问题。
- **不确定性下的预案参数化**：用「路径无关基准方案 + 观测桶→方案选择规则」，不要用逐桶独立变量（样本外塌缩 38%）；
  在样/样本外目标值都写进 `results.json`，`out_of_sample=true` 且**独立种子**。
- **门槛不可行时的定量探针**：整体缩放基准方案（乘子 $f$）扫描，报"做到零违约需要的规模与代价"，
  并与"若把容量硬约束放宽到 $\bar P+k$ 栏"的读法互换（两者是同一冲突的两种表述）。


## 八、交付域、松弛与派生度量（2026-09-04，2023 国赛 D 环节 6–8 实测）

- **交付域（可实施/可交付筛选）必须落在**「求解 → 归一化 → 锚点 → HV → 膝点 → **选择规则**」全链**：
  只在推荐点与检查器里过滤，会让「观测→动作」的规则仍选中已剔除的解；换域后**锚点、归一化、HV、膝点全部重算**（本例子前沿 HV 0.573680 → 0.501134，膝点 #73 而推荐 #82）。
- **交付域与门槛并列汇报**：被支配但可行的端点（如零租用 = #80，代价 Z1 ×1.79）要保留为**门槛选项**并标支配关系；
  「经验缩容能满足」与「重解 MILP 才满足」的代价差一个量级（×3.0 vs ×1.79）⇒ **门槛一律重解，不靠缩放**。
- **`n_binding == n_solutions` 即红旗**：某个界在**所有**解上都取等 ⇒ 它实际上是未被记载的常数，
  按 SOP §5「顶格率」三步处置（补编号 + 代价扫描 + 论文按假设口径写）。
- **随机/稳健性数字也要进 `results.json`**（顶层 `validation` 块，搬运层不重算）：否则写作环节按「数字唯一出处」
  去 `results.json` 找不到灵敏度数字，会退化成从 md 手抄 ⇒ 幻觉（实测抓到 `+3.77%` 应为 `+3.82%`）。
- **结构性零弹性要单独说明**：某参数只以比值进入模型（如 `conc_rate`、`lamb_mort` 只影响 `litter_det`）⇒
  扰动它「不动」不是脚本坏，而是**模型给了它零自由度**；必须写出这一推理，否则会被误判为检验漏跑。
