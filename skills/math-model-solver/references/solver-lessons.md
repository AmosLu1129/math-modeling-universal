# 求解环节历次实测教训（按题型检索）

> 本文件汇总历次赛题压测中的求解器与实现坑点，供遇到类似题型时按需查阅。

## 1. 大样本机器学习与特征工程（XJTU 校赛 C：LightGBM 87 万样本）
- 复用官方评分脚本（如 `calculate_metric.py` 的 `metric_by_cell`）时，输入 DataFrame 必须带 `_order` 列（`0..n-1`），否则按 cell 聚合排序会错位。
- SHAP 优先用 LightGBM 原生 `model.predict(X, pred_contrib=True)`（TreeSHAP，末列是 bias），不强依赖 `shap`（其依赖 `numba`/`llvmlite`，部分环境安装易失败）。
- 训练时长预算按最坏情况估算（单折时间 × 折数），长训练需每折落盘指标；大样本先把 `X`/`y` 转 `float32` 再进 `lgb.Dataset`。

## 2. 强结构整数规划与求解器选型（2024 国赛 C）
- 含“满种/最小面积/重茬”等强结构约束的 MILP，优先直接整数规划（OR-Tools CP-SAT），避免大 M 线性化导致的 LP 松弛过弱。
- 诊断流程：先用 LP 松弛看上界，再决定线性化方案；小数系数整体放大为整数（如 `SCALE=100`），还原结果时严格核对缩放链。
- 约 1.5 万变量 / 2 万约束规模求解 4–10 分钟属正常，提前启动并做好超时预案。

## 3. 图论网络与顶点割（2011 国赛 B）
- **候选集可达性 ≠ 指派后可达性**：必须对每个封堵点加硬截止时间约束，不能只按最近平台筛选后做瓶颈指派。
- **最小封堵集 = 最小顶点割**：节点分裂（入→出容量 1 仅限候选封堵点），多出口连虚拟汇，求完必用“删点后源到所有出口断开”的独立路径搜索验证。

## 4. 纯多目标 ε-约束 + 随机预案集（2023 国赛 D）
- **解析锚点先于求解器输出**：动手写求解器前先手算闭式上下界；求解器结果超越解析界 = 约束/符号必有实现 bug。
- **长算保护**：耗时 >60s 的求解入口先 `mkdir(parents=True, exist_ok=True)` 并逐段增量落盘。
- **CP-SAT 提速四件套**：注入 LP 容量有效不等式 + `AddHint` 给下界/取整初解 + 循环对称破缺（如 `x[0] >= x[d]`）+ gap 达阈值即接受。
- **“能跑 ≠ 对”第二路径互检**：矩阵/解析口径 ↔ 事件仿真逐日口径互检；评估窗口必须长于最长生产管道（设 burn-in）；检查器按约束编号逐条覆盖，不可漏编。
- **无成本自由变量与方向审计**：自由变量必须补守恒式/闭式等式，辅助需求量变量不可写反不等式方向。
- **样本外塌缩与名义/实现约束差异**：随机规划默认「路径无关基准表 + 观测桶选预案」，同时报样本内与样本外指标；前沿子集筛选后必须重算锚点、归一化、HV（双实现交叉断言）与膝点。

## 5. 部分识别反演、非循环留出与后验口径统一（2026 MCM C）
- **区分「样本内可行性」与「非构造性 OOS 基线」**：单纯形/多面体反演把淘汰约束写进可行域后，100% 一致是构造性必然，不可充当预测精度；必须同时输出① 闭式充要条件交叉核对（如百分比制 $\max_e \sum_k \max(0, j_e - j_k) \le 1$）与② 至少三个无当周淘汰泄露的 OOS 基线（Naive 物理基准、时序顺延、留一季特征 Softmax），且统计「不同组别 CI 宽度」时务必保证对比子集严格两两互斥。
- **反演归因必配零反演直接通道 + BH-FDR**：从“结局 + 评委分”反演出的粉丝票再拿去做特征回归会带来机械相关放大；求解脚本需同批跑出直接生存 Logit（聚类稳健标准误）与控制评分的残差结局 LMM，输出 BH-FDR $q$ 值及 `underpowered` ($n<10$) 标记。
- **去除 $z$-score 消元参数与循环约束**：送入周内标准化的打分/转换函数只能用改变凹性的参数（Box-Cox $\lambda \in [0,1]$），禁止线性乘子 $\gamma$；争议样本全部隔离至 Train/Holdout 的 Holdout 集（30/4 划分），不得写入优化约束；前沿评估使用向量化批量核对全部 200 组后验抽样统一打表，剪枝低指标点后必须重算 `front_size` 与双实现 HV。
- **`key_metrics` 顶层契约**：`make_results.py` 主动维护 `results.json` 顶层 `key_metrics` 路径列表，使 `consistency_check.py` 聚焦核验核心结论而不被百项网格明细分心。
