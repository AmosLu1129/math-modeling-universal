# 模型检验与灵敏度分析

## 输入输出

- 输入：`work/results.json`、`work/model_doc.md`、`work/code/`、`work/constraint_check.md`
- 输出：`work/validation_report.md`、`work/final_models.md`（**定稿，权威**）

## 本环节硬门禁（不可跳过）

> 全文规则见 `_shared/references/model-first-sop.md`（§5 迭代预算、§6 能跑≠对）；复杂优化/OOD 实测案例见 `references/validation-lessons.md`。**本环节的使命是“证伪自己”，不是凑好看的图。**

1. **先查独立约束复核**：必须引用 `work/constraint_check.md`（逐条 C 编号 PASS/FAIL + 目标值独立复算偏差）。缺失或仍有 FAIL → 退回 `math-model-solver`。
2. **第一性原理、实证基准锚定与极端边界退化检验（2026 升级）**：
   - **退化一致性检验**：令扰动/摩擦/约束收紧参数退化到极端值（0 或 $\infty$）或压回上游简化口径，检验模型是否逐项退化为已知解析解或上游 LP/闭式锚点（写 `assert` 验证）。
   - **真实世界实证锚点点对点验真（无附件/开放题 `o_award` 必做）**：若阶段 2 收集了 `work/data_clean/benchmarks/` 的具象真实测量基准（如真实机型曲线、具体遗址参数），必须在此执行模型输出 vs 实测曲线的逐点残差、MAE/RMSE 校验并给出误差物理解释，禁止仅用抽象合成情景宣称有效。
   - **基线与消融对照（支撑 Before-vs-After 视觉证明）**：若主模型在简单基线之上做了升阶，必须给出同口径消融/基线对比，并在 `results.json` / `validation_report.md` 结构化落盘净收益明细表（供阶段 7 套用 `morandi-dumbbell` 等对比图），证明升阶确实带来可验证的精度或可行性增益。
   - **量纲与符号检验**：关键输出对输入参数的响应方向（正负号、单调性）必须符合物理/经济直觉；若出现反直觉翻转或平台期，必须修正离散步长/采样缺陷或给出可信机理解释（**存在反号点时严禁在表/图题中标称“单调”**）。
   - **标准指标定义域守卫**：凡标注为“归一化/概率/占比”的指标必须严格落在 `[0, 1]`（例如归一化超体积若外扩参考点，必须除以参考框体积或显式改名并注明参考点，严禁输出超出 `[0, 1]` 的归一化指标）。
   - **同表实验口径一致性与 CRN**：同一对比表、灵敏度表或先验压力测试表内各试验组必须共享同一套计算配置（同样本量 $N$、随机模型统一使用公共随机数 CRN 隔离种子噪声、同求解预算/交叉验证划分）；若个别行因算力刻意采用不同配置，必须作为显式列标出。
   - **主观先验压力测试**：对 `model_doc.md` 中所有标注 `[合理工程估计]` 或 `[主观拍定先验]` 的参数或混合比例进行大跨度扰动测试，检验主力决策是否保持稳健。
   - **离散度相变、严格内点与跨节口径一致**：当点估计（如 MaxEnt）会人工压平离散度时，必须在「离散度比 × 相关性」平面扫描 2D 相图并标出结论翻转边界 $R^*(\rho)$；推荐超参/膝点紧贴搜索边界时必须扩界核查严格内点性；阶段 6 灵敏度表与阶段 5 主表必须基于**完全同一套后验抽样**计算并加精度断言，禁止前后口径打架。
   - **输入匹配的有效数字原则**：`results.json` 保留全精度用于计算溯源，但写入 `final_models.md` 与论文展示口径时应与输入估计精度匹配（常规统一 **2–3 位有效数字**，高不确定性结果给出区间），严禁将 $\pm 20\%$ 估算输入导出 4–5 位虚假精度，也禁止把 `1e-8` 类单元测试收敛残差包装成“模型验证亮点”。
3. **多目标小问必检前沿质量**：非支配性自检、前沿点数与目标覆盖区间、双实现超体积 HV 与参考点（确保定义域合规）、固定种子 ≥5 次重复均值±标准差、折中点选取规则可辩护性。
4. **不可行复核**：存在 `infeasibility_report.md` 时，独立复算其冲突子集是否成立，确认未通过暗改题面约束凑解。
5. **改动即回归**：若本环节修改了求解或评估代码，先重跑证明主输出不变（或发现模型缺陷时回阶段 5 全链重跑 + 重查约束）。
6. **出口自检**：`python _shared/scripts/check_formulation.py --work work/ --phase all` 退出码必须为 0：
   - `work/validation_report.md` 存在且必须同时包含**四要素**：
     ① **灵敏度与「So-What」结论**（±5/10/20% 或 Tornado/弹性表之外，必须明晰回答：谁是头号敏感参数？在其不确定区间内**核心决策/排名是否翻转**？）；
     ② **稳健性**（同口径重复模拟/噪声地板/交叉验证/主观先验压力测试）；
     ③ **适用边界与失效条件（Operating Limits）**（极端外部条件下模型何时失效）；
     ④ **独立成节的「模型自身弱点（Model Weaknesses）」**（诚实交代合成数据、未标定经验参数、简化假设等内在局限，严禁只写外部失效边界来回避模型短板）；
   - `results.json` 顶层含 `validation` 块；
   - `final_models.md` 不得残留「待环节 6 / TODO / 占位」；
   - `constraint_check.md` 判定列 FAIL 为 0。

## 常用检验维度（按题型选）

- **回归/机器学习**：R²/RMSE/MAE/MAPE、时间序列前滚/k 折 CV、残差图 + Q-Q 图 + 自相关检验、OOD 子集测试（如适用）。
- **优化/调度**：约束满足度、对偶/影子价格、LP 松弛界/解析上下界、确定性 Tornado + 随机水平/形状分离扰动 + 蒙特卡洛噪声地板（低于噪声地板的波动不宣称“敏感”）。
- **微分方程/机理**：步长收敛性、初值敏感性、合成数据反演校准、参数可辨识性与相关性热力图。

## final_models.md 定稿要求

整合全部迭代后的**权威版本**：完整带编号方程 + 全部参数数值代入 + 对应验证指标。写作环节与审查环节以此文件和 `results.json` 为唯一真源。
