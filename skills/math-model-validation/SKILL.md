# 模型检验与灵敏度分析

## 输入输出

- 输入：`work/results.json`、`work/model_doc.md`、`work/code/`、`work/constraint_check.md`
- 输出：`work/validation_report.md`、`work/final_models.md`（**定稿，权威**）

## 本环节硬门禁（不可跳过）

> 全文规则见 `_shared/references/model-first-sop.md`（§5 迭代预算、§6 能跑≠对）；复杂优化/OOD 实测案例见 `references/validation-lessons.md`。**本环节的使命是“证伪自己”，不是凑好看的图。**

1. **先查独立约束复核**：必须引用 `work/constraint_check.md`（逐条 C 编号 PASS/FAIL + 目标值独立复算偏差）。缺失或仍有 FAIL → 退回 `math-model-solver`。
2. **第一性原理与极端边界退化检验（2026 必做）**：
   - **退化一致性检验**：令扰动/摩擦/约束收紧参数退化到极端值（0 或 $\infty$）或压回上游简化口径，检验模型是否逐项退化为已知解析解或上游 LP/闭式锚点（写 `assert` 验证）。
   - **基线与消融对照**：若主模型在简单基线之上做了升阶，必须给出同口径消融/基线对比，证明升阶确实带来可验证的精度或可行性增益（而非无意义复杂化）。
   - **量纲与符号检验**：关键输出对输入参数的响应方向（正负号、单调性）必须符合物理/经济直觉；若出现反直觉翻转，必须定位原因或标为失效边界。
3. **多目标小问必检前沿质量**：非支配性自检、前沿点数与目标覆盖区间、双实现超体积 HV 与参考点、固定种子 ≥5 次重复均值±标准差、折中点选取规则可辩护性。
4. **不可行复核**：存在 `infeasibility_report.md` 时，独立复算其冲突子集是否成立，确认未通过暗改题面约束凑解。
5. **改动即回归**：若本环节修改了求解或评估代码，先重跑证明主输出不变（或发现模型缺陷时回阶段 5 全链重跑 + 重查约束）。
6. **出口自检**：`python _shared/scripts/check_formulation.py --work work/ --phase all` 退出码必须为 0：
   - `work/validation_report.md` 存在且必须同时包含「**灵敏度**（±5/10/20% 或 Tornado/弹性）」「**稳健性**（重复模拟/噪声地板/交叉验证）」「**适用边界与失效条件**」三要素；
   - `results.json` 顶层含 `validation` 块；
   - `final_models.md` 不得残留「待环节 6 / TODO / 占位」；
   - `constraint_check.md` 判定列 FAIL 为 0。

## 常用检验维度（按题型选）

- **回归/机器学习**：R²/RMSE/MAE/MAPE、时间序列前滚/k 折 CV、残差图 + Q-Q 图 + 自相关检验、OOD 子集测试（如适用）。
- **优化/调度**：约束满足度、对偶/影子价格、LP 松弛界/解析上下界、确定性 Tornado + 随机水平/形状分离扰动 + 蒙特卡洛噪声地板（低于噪声地板的波动不宣称“敏感”）。
- **微分方程/机理**：步长收敛性、初值敏感性、合成数据反演校准、参数可辨识性与相关性热力图。

## final_models.md 定稿要求

整合全部迭代后的**权威版本**：完整带编号方程 + 全部参数数值代入 + 对应验证指标。写作环节与审查环节以此文件和 `results.json` 为唯一真源。
